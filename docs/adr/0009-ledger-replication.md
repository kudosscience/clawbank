# ADR 0009: Ledger replicates over gossipsub mesh + request-response sync into a redb log with deterministic longest-valid-history fork-choice

The replicated ledger is an eventually consistent log of signed transfer batches: `gossipsub` mesh (`IdentTopic /ai-bank/transfer/1.0.0`, `MessageAuthenticity::Signed`, `ValidationMode::Strict`, `validate_messages=true`, `mesh_n=6`, peer-score P₁–P₇) for push propagation plus `request-response` CBOR (`/ai-bank/sync/1.0.0`, `SyncRequest{since_seq,limit}` → `SyncResponse{batches}`) for anti-entropy catch-up, persisted in a `redb 4.x` log (`balances`/`nonces`/`batches`/`meta`, one atomic `write_txn` per batch), reconciled by deterministic `longest-valid-history` fork-choice with the `sum==SUPPLY` filter. All messages are CBOR/JSON transfer batches (ADR 0007) signed under domain `b"/ai-bank/1/"` and verified against `PeerId`; Kademlia stays peer-routing only (ADR 0008) — see `research/ledger-replication` decision record.

## Status

Accepted — implements wayfinder ticket [#9 Ledger replication & supply invariant: fork-choice without a blockchain](https://github.com/kudosscience/ai-bank/issues/9) → `research/ledger-replication` (`docs/research/ledger-replication.md:1` on `research/ledger-replication`). Depends on ADRs 0001/0002/0004/0006/0007/0008.

## Context

FAL-2 requires fixed-supply virtual credits with no blockchain, no leader, and tolerance for partitions, offline peers, and N=50 Sybils — reconciliation must be local, deterministic, and clock-free, with `sum(balances)==SUPPLY` enforced on every apply. The swarm (ADR 0002) already provides gossipsub, request-response, and kad; the registry (ADR 0008) owns kad for peer routing; the data model (ADR 0007) owns `Transfer`/`SignedBatch` shapes. This decision assigns each transport its role and fixes the fork-choice rule.

## Considered Options

- **gossipsub mesh for push broadcast (chosen)** — `libp2p-gossipsub 0.49`, `D=6`/`D_low=4`/`D_high=12`, heartbeat 1s with IHAVE/IWANT + `MessageCache` dedup, `ConfigBuilder::validate_messages(true)` so the node calls `report_message_validation_result(Accept/Reject/Ignore)` only after application checks sig → nonce → dust → no-negative → `sum==SUPPLY`; invalid → `Validation::Reject` + P₄ peer-score penalty (decay to zero, retained across disconnects); P₅ app-score reserved for reputation weight later. Must set `validate_messages=true` — default `false` auto-forwards.
- **request-response CBOR for pull catch-up (chosen)** — `libp2p-request-response` `cbor::Behaviour` (`cbor4ii`) over Yamux/QUIC, one substream per request (`send_request` auto-dial, `send_request_with_addresses` when kad hasn't populated addrs), `Config::with_request_timeout` tuned off the gossipsub heartbeat path. Pattern: on reconnect/periodic tick `SyncRequest{since_seq: local_tip, limit: 64}` → `SyncResponse{batches}` → validate + apply in fork-choice order. Broadcast stays optimistic; sync repairs gaps (`mcache` window `history_length=5`/`history_gossip=3` only covers short partitions).
- **redb log for local durability (chosen)** — `redb 3.1+/4.x` (ACID MVCC, stable format since 1.0, actively maintained) tables `balances`/`nonces`/`batches`/`meta` (ADR 0007); `sled 0.34.7` rejected (beta, unstable format pre-1.0, last stable 2021) unless lock-free write throughput is measured dominant. O(accounts) sum mitigated by `total: u64` fast-path + periodic `u128` full-scan audit; per-batch (e.g. 64 transfers) verify keeps cost bounded.
- **Deterministic longest-valid-history fork-choice (chosen)** — `valid(history) := history[0]==genesis ∧ ∀ batch: verify_batch` in fail-fast order (Ed25519 `b"/ai-bank/1/batch:"` sig vs `from` PeerId → `nonce==expected[from]` 1-indexed per-sender → `DUST_THRESHOLD ≤ amount ≤ MAX_AMOUNT` → `apply_on_copy` no-negative → `sum==SUPPLY` via `u128`); `fork_choice := valid.max_by(tip_seq, -blake3(canon), -tip_author_bytes)` (logical clock, unbiased hash, total order for `cargo test` determinism). Vector clocks/HLC (`(pt,counter,PeerId)`) kept as causal metadata/debug only; LWW-per-key rejected (silently drops writes, breaks supply); reputation-weighted (`tip_seq + α·sum_reputation`) deferred to FAL-3 behind a flag to avoid the ledger→reputation→fork-choice loop the Sybil harness must catch (ADR 0004/0006, #11). Same-nonce different-payload → equivocation proof gossipped on `/ai-bank/evidence/1.0.0` + P₄ slash; overspend across branches resolves by single surviving history (loser tail replays as `InsufficientFunds`). Recovery by signed `Checkpoint{seq,history_hash,signers}` over `b"/ai-bank/1/checkpoint:"` on `/ai-bank/checkpoint/1.0.0` + release tag + Rekor (ADR 0005/0006), pinned as new anchor; maintainer key + `ceil(known/2)` quorum for FAL-2 liveness, never DHT quorum.
- **Kademlia reserved for peer routing (chosen)** — `start_providing`/`get_providers` rejected for ledger push (pull pointers only, 48h/36h expiry, no push event, no mesh scoring); kept only for optional `/ai-bank/snapshot/<seq>` shard-pointer index later. `identify → kad` wiring (ADR 0008) feeds request-response dialing, not transfer broadcast.
- **Genesis/supply mechanics** — `genesis.json` `{supply: u64, balances: BTreeMap<PeerId,u64>, checkpoint_seq: 0, history_hash: blake3, sig: maintainer over b"/ai-bank/1/genesis:"}` shipped with binary (or HTTPS + sig + hash-pin), `sum==SUPPLY` verified before seq-0 insert; allocation choice deferred to #12; per-sender `seq` persisted atomically with balances so crash can't advance nonce without balance.

## Consequences

- Crate pin: `libp2p 0.56` (`gossipsub 0.49`, `request-response` cbor via `cbor4ii`, `kad 0.48`, `identify`, `redb 4.x`) + `blake3` + `ed25519-dalek` interop per ADR 0001; MSRV 1.83.
- Service layer stays transport-blind (ADR 0002/0007): gossipsub handler, request-response handler, and localhost HTTP handler all call `service::validate/apply/balance`.
- FAL-2 harness (ADR 0006) implements this ADR as `cargo test`: integrity (double-spend/replay/supply/partition), dust 10×, Sybil N=50, circular/whitewash — all local, no central infra.
- Kademlia DHT semantics never gate ledger liveness; ledger never depends on DHT record TTLs.
